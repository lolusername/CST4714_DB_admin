A view is a named query. Start with this working version:

```sql
CREATE OR REPLACE VIEW metro_support.active_ticket_queue AS
SELECT t.ticket_id, t.subject, t.status, t.priority, t.opened_at
FROM metro_support.tickets AS t
WHERE t.status IN ('new', 'open', 'in_progress');

SELECT * FROM metro_support.active_ticket_queue ORDER BY ticket_id;
```

It should return 7 rows. Add the assigned staff member's name as a **new final
column** called `assignee_name`. Use a LEFT JOIN so tickets 1004 and 1009 remain.

Keep the original view's column names and order. PostgreSQL's CREATE OR REPLACE
VIEW permits appending columns but does not let you arbitrarily reorder existing
ones. Check both the row count and those two unassigned ticket IDs after changing it.

A view can limit exposed columns, but hiding columns in a view is not sufficient
access control if the same user can still read the base table. Week 6 tests grants.

## 2. Investigate a Missing ID

Run this setup only for the disposable notes table:

```sql
DROP TABLE IF EXISTS metro_support.change_notes;
CREATE TABLE metro_support.change_notes (
    note_id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    change_name text NOT NULL,
    created_at timestamptz NOT NULL DEFAULT now()
);
```

Run the following block together, then inspect the result:

```sql
BEGIN;
INSERT INTO metro_support.change_notes (change_name)
VALUES ('Created dashboard view') RETURNING note_id;
COMMIT;

BEGIN;
INSERT INTO metro_support.change_notes (change_name)
VALUES ('Cancelled change') RETURNING note_id;
ROLLBACK;

BEGIN;
INSERT INTO metro_support.change_notes (change_name)
VALUES ('Added assignee name') RETURNING note_id;
COMMIT;

SELECT note_id, change_name
FROM metro_support.change_notes ORDER BY note_id;
```

The first and third insertions persist. The middle insertion does not. Explain
why a gap in the IDs is consistent with a successful rollback. An identity
sequence allocates numbers; it does not promise a gapless count of committed rows.
The explicit commits also make the intended boundaries hold when the editor sends
the whole example as one batch.
