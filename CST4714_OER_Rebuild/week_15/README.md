# Week 15: Synthesis, Portfolio Evidence, and Final Presentations

## The Week's Question

How do you make database skill visible through a safe demonstration, reproducible
artifact, and evidence-based interview explanation?

## What You Will Be Able to Do

- review a system through model, query, access, performance, and recovery evidence;
- present a final project without exposing credentials;
- turn one course concept into a useful GitHub artifact;
- write a resume bullet and STAR-R interview story from real evidence; and
- identify one next skill without overstating production experience.

## Day 2: Final Demonstrations and Career Translation

Present the final project according to the
[canonical final-project requirements](../final_project.md). Use prepared,
redacted evidence and a non-live fallback.

Then turn one project decision into a resume bullet and STAR-R interview story.
This reflection may be submitted through the course's final Brightspace prompt;
it is not a new final-project deliverable.

## Optional Industry Extension: Sixty-Second Interview Recording

This activity is optional, ungraded, and does not add a submission.

Record or write a sixty-second answer to: "Tell me about a database problem you
investigated." Use situation, your task, one technical action, observable result,
and reflection. Name one query, plan, policy test, restore check, or incident
artifact as evidence. Listen or reread once and remove unsupported claims such as
"production scale," "zero downtime," or "fully secure" unless your evidence
actually establishes them.

## Final Self-Check

You should be able to answer:

1. What did you build or investigate?
2. Which evidence shows it worked?
3. Which failure or bad state did you consider?
4. Which tradeoff did you accept?
5. What would you inspect next in production?
