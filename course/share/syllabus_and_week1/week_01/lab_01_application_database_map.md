# Lab 1: Map an Application to Its Database

## Purpose

Connect a familiar application to the data, questions, and technical components
behind it while learning GitHub's browser editor.

This is individual work completed in class. Submit one Markdown file.

## Choose an Application

Choose one application domain that you understand well enough to discuss:

- music or video streaming;
- an online store or food-delivery service;
- a game with players, matches, or inventory;
- transit or public-service requests; or
- another instructor-approved example.

## Create the File in GitHub

Open your course repository, choose **Add file** and **Create new file**, and name
the file `week_01/app_database_map.md`. Paste the template below and replace the
prompts with your own example.

```markdown
# Application and Database Map

Application: [name or type of application]

## Data it needs

- [one entity or record type]
- [a second entity or record type]
- [a third entity or record type]

## Questions it must answer

1. [one useful question]
2. [another useful question]

## Trace one action

User action: [for example, add a song to a playlist]

Request path: client -> application/API -> identity or permission check -> DBMS -> stored data -> result

## First model idea

Facts that could become relational tables: [your answer]

Facts that might fit together in one document: [your answer]

One question I still have: [your answer]
```

Use GitHub's **Preview** tab to check the headings and lists. Commit the file with
a short message such as `Add week 1 application database map`.

## Submit One Thing

Submit the URL to `app_database_map.md` in Brightspace. The file is complete when
it names at least three kinds of data, asks two database questions, traces one
request, and proposes both a table idea and a document idea.

Do not include a password, connection string, API key, private account address,
or real personal data.
