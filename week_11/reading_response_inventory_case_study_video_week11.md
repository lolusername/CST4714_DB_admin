# Week 11 Day 2 In-Class Response
## Event-Driven Inventory Platform Case Study (MongoDB Video)

## Activity Type
Short individual Day 2 response tied to MongoDB basics, beginner MQL, and introductory modeling

## Purpose
This assignment uses the same MongoDB inventory-platform video from Week 10, but it now serves a different purpose.

Instead of treating the video as a follow-up to an advanced modeling week, students should now use it as:
- a beginner modeling case study
- a way to see documents and relationships in context
- and a way to connect simple MongoDB ideas to a realistic application

## Submission Format
Submit your response directly in the Brightspace text box and answer all prompts.

Requirements:
- 250-400 words total
- full sentences
- refer to at least two specific timestamps from the video
- make an argument, not just a summary

You may organize the response as short paragraphs or clearly labeled sections.

Do not upload a markdown file for this assignment.

## Prompts

### Prompt 1
What kind of application is this inventory platform, and why does MongoDB make sense for a system like this?

Keep your answer beginner-friendly.
Focus on:
- documents
- flexible structure
- changing data
- or event records

### Prompt 2
Name one kind of data or relationship you noticed in the video that seems important.

Examples:
- products
- stock changes
- warehouse or location data
- inventory events

Explain why that data matters to the application.

### Prompt 3
If you were modeling one part of this system, where would you most likely embed data, and where would you most likely keep a reference?

Your answer must name:
- one thing you would embed
- one thing you would reference
- and one reason for each choice

### Prompt 4
Name one MongoDB question or report you think this application would need often.

Keep it simple.
Examples:
- Which products are low in stock?
- What changed in inventory today?
- Which warehouse had the most updates this week?

Explain why that question matters.

## Evaluation (Participation / 10)
- 4 pts: all prompts are addressed
- 3 pts: timestamps are used correctly
- 3 pts: response connects the video to beginner MongoDB concepts instead of only retelling the video
