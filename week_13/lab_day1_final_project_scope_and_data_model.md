# Week 13 Lab Day 1
## Final Project Scope and Data Model Build

## Purpose
Today you will turn your final project idea into a buildable database model.

The goal is not to finish the whole project today.
The goal is to leave class with a small project scope and a first real data model.

## Individual Work Only
This lab is individual.
There is no group work.

## What To Do

### 1. Re-State Your Project
Write:

1. project title
2. platform path: Supabase/Postgres, MongoDB/Atlas, or both
3. one-sentence problem statement
4. who would use this database
5. what the database helps them track or answer

### 2. Cut the Scope Down
Write one paragraph explaining what your project will not do.

Examples:
- It will track club events, but it will not handle payments.
- It will track support tickets, but it will not include a full chat system.
- It will track inventory changes, but it will not build a full e-commerce store.

### 3. Build the First Data Model

For Supabase/Postgres:
- list 3-5 tables
- list the most important columns for each table
- identify primary keys
- identify at least two relationships
- identify one likely index

For MongoDB/Atlas:
- list 2-4 collections
- write one example document for the main collection
- identify one embedded structure
- identify one referenced relationship
- identify one likely index

For both:
- explain what each platform owns
- keep the split very small
- explain why one platform alone is not enough

### 4. Scaling Reflection
Answer:

1. What part of your project could grow the fastest?
2. What would be the first capacity problem: storage, reads, writes, slow queries, or messy data?
3. If this were a MongoDB sharded collection, what field might be tempting as a shard key?
4. Why might that shard key be good or bad?

## In-Class Checkpoint
Submit one Brightspace text response.

Include:
1. project restatement
2. scope cut paragraph
3. data model draft
4. scaling reflection

## Success Standard
You are successful if another person can read your response and understand what database you are building, what data it stores, and why the scope is small enough to finish.
