## Class Structure

First part:
- review the course map
- connect relational databases, MongoDB, cloud platforms, performance, security, backup/recovery, and reliability
- show how database administration is more than writing queries

Middle part:
- use the notebooks as short review demos
- translate course concepts into portfolio and interview language
- identify evidence students already have from labs and the final project

Final part:
- students complete the final in-class GitHub concept artifact
- each student creates one public or shareable GitHub page/file that explains one course concept
- students submit the GitHub link in Brightspace

## Learning Outcomes
By the end of the last class, students should be able to:
1. explain the main responsibilities of database administration
2. connect course labs to real operational skills
3. describe one database concept clearly to a non-expert
4. show one GitHub artifact that demonstrates technical communication
5. talk about the final project in interview language
6. identify what remains before the final project due date of May 26, 2026

## Recommended Instructor Flow
1. Start with `Week_15_Last_Class_Database_Admin_Portfolio_Review.pptx`.
2. Keep the review high-level, but stop for concrete examples when students seem uncertain.
3. Use `final_class_sql_review_notebook.ipynb` to review schema, constraints, joins, indexes, transactions, and backup-style export.
4. Use `final_class_document_modeling_review_notebook.ipynb` to review JSON, document modeling, aggregation, relationships, and NoSQL tradeoffs.
5. Have students open `job_interview_portfolio_guide.md`.
6. Run `lab_final_github_concept_artifact.md` as the final in-class lab.
7. End with students submitting one GitHub URL and one sentence explaining what concept they chose.

## Success Standard
The last class is successful if each student can point to one concrete artifact and say:

`This shows that I can explain and apply a real database administration concept.`
